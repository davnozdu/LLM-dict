# Ревизия кода LLM-dict

Дата: 2026-09-14. Версия: 0.15.2. BUG-001—BUG-021 исправлены в текущем
изменении; описания ниже сохранены как аудит и условия регрессии.
Исходный коммит: `fbcf391`.
Основной путь сборки — GitHub Actions (`.github/workflows/build.yml`), согласно
уточнению пользователя. Локальные проверки ниже — диагностические результаты
этой ревизии; они не являются результатами сборки GitHub.
P1 — высокий приоритет, P2 — средний, P3 — низкий.
Подтверждение по коду означает анализ конкретного пути исполнения, а не ручное
воспроизведение в работающем приложении. Проверки не использовали пользовательские
ключи, микрофон, буфер обмена или облачные запросы.

## Первая ревизия — сохранённые находки

### BUG-001 · P1 · Буфер теряется при ошибке действия

- Код: `src/engine.rs:853–867`, `src/engine.rs:923–929`, `src/insert.rs:62–80`.
- Условие: действие скопировало выделение, затем чтение файла сведений или модель
  вернули ошибку.
- Результат: прежний буфер уже затёрт синтетическим Cmd+C и не восстанавливается,
  даже с включённым `restore_clipboard`; `previous` теряется при выходе через `?`.
- Исправление: хранить снимок и счётчик изменения вне ошибочного пути; восстанавливать
  только собственное изменение, не затирая последующие копирования пользователя.
- Подтверждение: по коду.

### BUG-002 · P1 · Отложенное восстановление затирает новое копирование

- Код: `src/insert.rs:128–132`.
- Условие: пользователь копирует новый текст между вставкой и истечением 400 мс.
- Результат: фоновый поток безусловно записывает старое значение поверх нового.
  Аналогичная гонка возможна между несколькими вставками приложения.
- Исправление: проверять принадлежность текущего изменения перед восстановлением;
  сериализовать собственные операции с буфером.
- Подтверждение: по коду.

### BUG-003 · P2 · Действия обходят лимит истории

- Код: `src/engine.rs:920–921`; сравнить с `src/engine.rs:802–807`.
- Условие: многократные действия над текстом без диктовки.
- Результат: записи добавляются в память и на диск без `truncate`/`trim`.
- Исправление: единый синхронизированный путь записи и ограничения истории.
- Подтверждение: по коду.

### BUG-004 · P2 · Отметка собственного текста буфера не сбрасывается

- Код: `src/clipboard.rs:139–140`, `src/clipboard.rs:175–178`.
- Условие: вернуть запись A из истории, скопировать B, затем вручную скопировать A.
- Результат: A снова игнорируется, поскольку `ours` хранит A до следующего
  `mark_ours`, а не только до обработки собственного изменения.
- Исправление: связывать отметку с конкретным изменением пастборда и поглощать её.
- Подтверждение: по коду.

### BUG-005 · P2 · Срок хранения буфера не меняется на лету

- Код: `src/clipboard.rs:145–157`, `src/app.rs:1129–1135`.
- Условие: изменить «Хранить дней» в настройках.
- Результат: ротация продолжает использовать значение, захваченное при запуске.
- Исправление: передавать актуальный срок фоновому потоку и применять новую политику.
- Подтверждение: по коду.

### BUG-006 · P3 · Пустой ключ транскрибации обнаруживается только сервером

- Код: `src/providers.rs:148–178`; сравнить с `require_key` в `run_prompt`.
- Условие: облачное распознавание без сохранённого ключа.
- Результат: аудио отправляется без авторизации, вместо локального сообщения
  о недостающем ключе приходит ошибка сервиса.
- Исправление: проверять ключ до создания и отправки запроса, сохранив поддержку
  локальных серверов без ключа.
- Подтверждение: по коду.

### BUG-007 · P2 · Неатомарная запись настроек допускает их потерю

- Код: `src/config.rs:375–391`, `src/config.rs:434–439`.
- Условие: сбой записи после обрезания существующего `config.toml` или завершение
  процесса во время записи.
- Результат: повреждённый TOML при загрузке заменяется значениями по умолчанию;
  последующее сохранение может затереть исходные настройки.
- Исправление: временный файл рядом с конфигом, синхронизация и атомарная замена;
  сохранить повреждённый исходник для восстановления.
- Подтверждение: по коду; аварийное завершение не моделировалось.

## Продолжение ревизии

### BUG-008 · P1 · Push to Talk теряет отпускание, пока рабочий поток занят

- Код: `src/hotkey.rs:264–267`, `src/engine.rs:329–333`, `src/engine.rs:400–401`.
- Условие: нажать и отпустить клавишу до того, как `audio::start` завершится и
  рабочий поток выставит `recording = true`. Это возможно и во время обработки
  предыдущей диктовки: события копятся в канале, а флаг записи остаётся false.
- Результат: `Matcher` отправляет StartRecording, но не отправляет StopRecording
  при отпускании с флагом false. Позже микрофон включается уже при отпущенной
  клавише и работает до следующего события или автоостановки.
- Исправление: отслеживать намерение начать/закончить запись в автомате клавиш,
  независимо от запаздывающего подтверждения рабочего потока.
- Проверка: сценарий `hold_release_before_worker_ready_must_enqueue_stop`.

### BUG-009 · P2 · Toggle переключается от автоповтора и посторонней клавиши

- Код: `src/hotkey.rs:255–267`, `src/hotkey.rs:332–334`.
- Условие: держать сочетание Toggle с обычной клавишей до автоповтора; либо
  нажать другую букву, продолжая держать модификатор диктовки.
- Результат: проверка `active && is_down` срабатывает заново и отправляет Stop,
  хотя новое нажатие самого сочетания не происходило. `HeldKeys::apply` считает
  повторный KeyDown нажатием даже для уже зажатой клавиши.
- Исправление: переключать только на переходе «сочетание не собрано → собрано»;
  подавлять автоповтор и не относящиеся к этому переходу клавиши.
- Проверки: `toggle_autorepeat_must_not_stop_recording`,
  `toggle_unrelated_key_must_not_stop_recording`.

### BUG-010 · P2 · Отпускание вложенного сочетания повторно включает диктовку

- Код: `src/hotkey.rs:237–271`.
- Условие: диктовка в Hold на правом Cmd; действие на правом Cmd+C.
  Действие отменило запись, затем пользователь отпускает C раньше Cmd.
- Результат: `fired` сбрасывается, а оставшийся Cmd подходит под диктовку;
  отправляется StartRecording прямо на событии отпускания C.
- Исправление: после действия блокировать его короткую комбинацию до отпускания
  соответствующего удержания, а не запускать её повторно при разборе сочетания.
- Проверка: `releasing_nested_action_must_not_restart_dictation`.

### BUG-011 · P2 · Локальный поставщик скрывает общие настройки действия

- Код: `src/app.rs:2168–2187`; скрытые поля находятся ниже в том же
  `ui_action_editor`, начиная с `src/app.rs:2232`.
- Условие: выбрать поставщика «Локальная модель» в редакторе действия.
- Результат: ранний `return` скрывает промпт, способ вывода, файл данных и
  «Использовать после диктовки». Новое локальное действие нельзя полноценно
  настроить без временного переключения обратно на облачного поставщика.
- Исправление: ограничить ветвлением только настройки облачной модели/ключа;
  общую часть редактора показывать для всех поставщиков.
- Подтверждение: по коду интерфейса; GUI не запускался.

### BUG-012 · P2 · Переключатель режима на вкладке «Статус» не управляет обработкой

- Код: `src/app.rs:775–784`, `src/engine.rs:711–718`, `src/config.rs:406–429`.
- Условие: выбрать «Перевод», «Корректура» или «Без обработки» на вкладке «Статус».
- Результат: UI меняет старое `cfg.llm.mode`, но конвейер использует только
  `cfg.actions`. Выбор Raw не отключает отмеченные действия. После перезапуска
  ненулевой режим мигрирует в новое действие, вместо переключения текущего режима;
  повторение этой операции может накопить несколько действий обработки.
- Исправление: перевести быстрый переключатель на актуальный механизм действий
  либо убрать устаревший элемент управления.
- Подтверждение: по всем обращениям к `llm.mode` и месту вызова `normalized`.

### BUG-013 · P2 · Локальный перевод после диктовки бракуется как смена языка

- Код: `src/engine.rs:647–650`, `src/local_llm.rs:398–414`.
- Условие: перевод на английский отмечен «после диктовки», файла контекста нет;
  выбран локальный поставщик или срабатывает локальный fallback.
- Результат: выбирается `Guard::Correction`. Корректный английский ответ на
  русскую фразу отбрасывается проверкой письменности, вставляется русский оригинал.
  Аналогично проверки длины мешают суммаризации и другим преобразованиям.
- Исправление: выбирать проверку по типу задачи, а не по моменту её запуска.
- Проверка: `translation_selected_after_dictation_must_be_accepted` проверяет
  реальный `sanitize` с тем Guard, который выбирает `apply_action`; модель не запускалась.

### BUG-014 · P1 · Ошибка чтения файла сведений превращается в запрос без сведений

- Код: `src/engine.rs:720–735`.
- Условие: у действия после диктовки указан файл, но он удалён, недоступен,
  слишком велик или не читается как UTF-8.
- Результат: `missing_context()` не срабатывает, потому что путь непустой;
  ошибка `load_context()` превращается в None, после чего действие всё равно
  выполняется и его ответ может заменить диктовку. Сообщения пользователю об
  утрате обязательных данных нет, остаётся только запись в журнале.
- Исправление: пропускать это действие при ошибке чтения с явным сообщением,
  сохраняя текущий текст, как уже делается при ошибке модели.
- Подтверждение: по коду; путь ручного действия в `run_action` такую ошибку возвращает.

### BUG-015 · P2 · Обычные слова в промпте ошибочно делают внешний файл обязательным

- Код: `src/actions.rs:226–234`, `src/engine.rs:857–861`.
- Условие: задать без файла промпт «Сократи текст пользователя, сохрани всю информацию».
- Результат: подстрока `информаци` делает `missing_context()` истинным; действие
  отказывается выполняться, хотя все данные — уже в выделенном тексте. Аналогично
  ломаются инструкции со словами «контекст», «данные», «файл» в другом значении.
- Исправление: явное свойство «нужен файл» у действия; эвристику оставить подсказкой,
  а не условием запрета запуска.
- Проверка: `rewrite_prompt_without_external_file_must_be_allowed`.

### BUG-016 · P1 · Сохранение ключа Groq расходится между диктовкой и действиями

- Код: `src/app.rs:498–514`, `src/app.rs:1645–1650`,
  `src/config.rs:452–459`, `src/engine.rs:549`.
- Условие A: в режиме хранения в файле сохранить ключ на вкладке «Действия»,
  затем поменять его в общих настройках.
- Результат A: общие настройки обновляют `cfg.api_key` и кеш `shared.api_key`,
  но не `provider_keys["groq_api_key"]`. Приоритет у словаря: действия и следующий
  запуск снова используют старый ключ, несмотря на сообщение об успешном сохранении.
- Условие B: поменять ключ Groq на вкладке «Действия» во время работы приложения.
- Результат B: `set_key_for` обновляет хранилище, но не `shared.api_key`, поэтому
  облачная диктовка продолжает отправлять прежний ключ до перезапуска.
- Исправление: единая операция сохранения, синхронизирующая оба UI и рабочий кеш;
  один канонический источник ключа в конфиге.
- Проверка A: `main_settings_key_change_must_replace_action_key`, с тестовыми строками
  в конфиге в памяти. Keychain и настоящие ключи не использовались. B подтверждено по коду.

### BUG-017 · P1 · Параллельные действия конкурируют за выделение, вставку и статус

- Код: `src/engine.rs:365–375`, `src/engine.rs:826–828`,
  `src/engine.rs:853–883`, `src/engine.rs:932`.
- Условие: запустить второе действие или начать диктовку, пока первое действие
  ожидает ответ поставщика. Рабочий поток не блокирует такой запуск.
- Результат: отдельные потоки независимо выполняют Cmd+C и Cmd+V с общим буфером
  и текущим выделением. Медленное первое действие может затереть результат второго;
  завершение любого потока ставит Idle даже при продолжающейся записи/обработке.
  Мьютекс локальной модели защищает только генерацию, не весь цикл действия.
- Исправление: явное владение операцией, согласованная очередь/отказ при занятости
  и сериализация операций с выделением и буфером.
- Подтверждение: по путям исполнения; живые приложения и буфер не затрагивались.

### BUG-018 · P1 · «Заменить выделенное» вставляет результат в чужое активное окно

- Код: `src/engine.rs:853–879`, `src/insert.rs:120–126`.
- Условие: запустить действие Replace в редакторе A и переключиться в окно B,
  пока модель отвечает.
- Результат: исходные приложение/выделение не запоминаются и не проверяются;
  синтетический Cmd+V вставляет результат в B, потенциально заменяя другой текст.
  Это возможно и с единственным действием, независимо от BUG-017.
- Исправление: проверить исходную цель перед заменой; при смене цели предложить
  результат через буфер/историю вместо автоматической вставки.
- Подтверждение: по отсутствию фиксации/проверки цели в пути Replace; GUI не запускался.

### BUG-019 · P2 · Просроченные записи буфера удаляются только с диска

- Код: `src/clipboard.rs:93–106`, `src/clipboard.rs:127–129`,
  `src/clipboard.rs:145–157`.
- Условие: история содержит записи старше срока хранения; запустить приложение
  или дождаться часовой ротации.
- Результат: `History::new` загружает записи до стартовой ротации, а `rotate`
  изменяет только файл. Просроченный текст остаётся доступным в UI, поиске и
  листании до вытеснения из памяти или следующего перезапуска.
- Исправление: применять один cutoff к дисковой и оперативной истории под
  согласованной синхронизацией; на старте чистить до загрузки записей в UI.
- Подтверждение: по коду; настоящая история не читалась и не менялась.

### BUG-020 · P2 · Звук с частотой ниже 16 кГц ускоряется при преобразовании

- Код: `src/audio.rs:91–102`, `src/audio.rs:245–271`.
- Условие: входной WAV или поток микрофона с частотой 8 кГц.
- Результат: преобразователь выдаёт максимум один выходной сэмпл на входной,
  хотя нужно два. 8000 сэмплов секунды звука остаются 8000, но далее трактуются
  как 16 кГц: длительность 0,5 с, частоты/темп удваиваются, распознавание портится.
- Исправление: поддержать повышение частоты корректным ресэмплером либо явно
  отклонять неподдерживаемую частоту до обработки.
- Проверка: `wav_8khz_one_second_must_stay_one_second`, синтетический WAV в
  отдельном временном каталоге, без микрофона.

### BUG-021 · P1 · Запрос к локальному серверу может задержать даже начало диктовки

- Код: `src/server.rs:228–247`, `src/server.rs:286–331`,
  `src/engine.rs:287–291`, `src/engine.rs:685–689`.
- Условие: сервер занят долгой генерацией или записью потока медленному клиенту;
  у приложения включена выгрузка по простою и выключено постоянное удержание LLM.
  После 30 с без событий рабочий поток попадает в `unload_idle`.
- Результат: проверка простоя делает блокирующий `llm.lock()`, тогда как сервер
  держит этот мьютекс до конца генерации и отправки ответа. Рабочий поток перестаёт
  читать события горячих клавиш до освобождения модели. Даже начало записи,
  не требующее LLM, зависит от внешнего клиента. Проверка Stage до серверного
  запроса этого не предотвращает; в очереди сервера Stage также не перепроверяется.
- Исправление: `try_lock` для необязательной проверки выгрузки, ограниченная
  очередь с приоритетом диктовки, отделение отправки ответа от владения моделью.
- Подтверждение: по времени жизни блокировок и пути рабочего потока;
  модель и сетевой сервер для проверки не запускались.

## Проверки продолжения ревизии

Запущен изолированный стенд с подключением исходных модулей через `#[path]`.
Восемь проверок ожидаемого поведения завершились ошибками assert, подтверждая
семь находок (у BUG-009 два сценария):

| Проверка | Баг | Фактический результат |
|---|---|---|
| Отпускание до готовности рабочего потока | BUG-008 | `[]` вместо `[StopRecording]` |
| Автоповтор Toggle | BUG-009 | лишнее событие остановки |
| Посторонняя буква при удержании Toggle | BUG-009 | лишнее событие остановки |
| Отпускание C после вложенного действия | BUG-010 | лишнее событие начала записи |
