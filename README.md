# LLM-dict

Диктовка для macOS: удерживаете клавишу, говорите, отпускаете — текст появляется там, где стоит курсор.

Распознавание идёт через любой OpenAI-совместимый API (по умолчанию Groq с `whisper-large-v3-turbo`), при желании текст сразу проходит через языковую модель — перевод, корректура или произвольная переработка по своему промпту.

## Что умеет

- **Диктовка по сочетанию клавиш.** Сочетание задаётся нажатием, а не выбором из списка: нажимаете «Задать сочетание» и зажимаете нужные клавиши, до трёх. Приложение проверяет, свободно ли оно — сверяется с системными сочетаниями macOS и со списком тех, что заняты в большинстве программ. Два режима: **Push to Talk** (держите клавишу, пока говорите) и **переключатель** (нажали, говорите, нажали ещё раз). Клавиши только прослушиваются, их обычное действие сохраняется.
- **Индикатор у курсора.** Пока идёт диктовка, рядом с курсором висит небольшая плашка со стадией и пульсацией по громкости — видно, что микрофон слышит, даже когда окно закрыто. По окончании исчезает.
- **Вставка под курсором** в любое приложение — через буфер обмена с восстановлением прежнего содержимого.
- **Пост-обработка моделью.** Без обработки, корректура пунктуации, перевод на заданный язык или свой промпт.
- **Работа в фоне.** Иконка в верхней панели меняет цвет по стадии: серый — готов, красный — запись, оранжевый — распознавание, синий — обработка, зелёный — вставка. Иконку в доке можно включить или убрать.
- **История диктовок** с исходным распознаванием, результатом, задержкой и длительностью речи.
- **История буфера обмена.** Всё скопированное запоминается и доступно по своему сочетанию: открывается окно с поиском, стрелками выбираете нужное, Enter — и оно вставляется туда, откуда вы пришли. Хранится 30 дней, срок настраивается, старое удаляется само.
- **Действия над выделенным текстом.** Выделяете текст, нажимаете своё сочетание — перевод, корректура или что угодно, описанное промптом. Результат ложится в буфер обмена, у курсора появляется плашка «в буфере», вставляете сами. Либо заменяет выделенное на месте — это настраивается.
- **Тихая обработка.** Обычная клавиша сочетания не уходит дальше в систему, поэтому программа не получает незнакомое сочетание и не отвечает системным писком. Модификаторы пропускаются всегда — иначе сломались бы обычные ⌘C и ⌘V.
- **Пределы записи.** Диктовка обрывается сама после минуты (настраивается) и после нескольких секунд тишины — зажатая и забытая клавиша больше не пишет в пустоту.
- **Автозапуск** при входе в систему.
- **Обновление одной кнопкой** — приложение само проверяет релизы, скачивает образ и подменяет себя. Карантин при этом не появляется.
- API-ключ хранится в системной связке ключей; при желании можно переключить на файл настроек.

## Установка

Готовая сборка — в [релизах](../../releases): скачать `.dmg`, открыть, перетащить `LLM-dict.app` в `Applications`.

Артефакты промежуточных сборок лежат во вкладке Actions. Учтите, что Actions архивирует артефакты сам, поэтому скачанный файл нужно сначала распаковать — внутри будет `.dmg`.

Сборка не нотаризована Apple, поэтому карантин снимается вручную:

```bash
xattr -dr com.apple.quarantine /Applications/LLM-dict.app
open /Applications/LLM-dict.app
```

Дальше во вкладке **Права** выдать два разрешения и **перезапустить приложение**:

| Разрешение | Зачем |
|---|---|
| Универсальный доступ | отправить ⌘V для вставки и ⌘C для чтения выделенного |
| Мониторинг ввода | получать клавиши раньше других программ |
| Микрофон | записать речь |

**«Мониторинг ввода» — не формальность.** Без него macOS отдаёт приложению только модификаторы, а нажатия обычных клавиш молча отсекает. Сочетания из одних модификаторов при этом работают как ни в чём не бывало — диктовка на правом ⌘ идёт, а перевод на ⌘⌥C молчит. Со стороны это выглядит как выборочный сбой приложения, хотя причина одна и та же.

Перехватчик работает на HID-уровне, а не на уровне сессии. Разница существенная: перехватчик сессии получает события уже после чужих перехватчиков, и сочетание, которое забрала другая программа, до нас просто не доходит — модификаторы приходят, а сочетание с буквой пропадает целиком. Именно за HID-уровень macOS и спрашивает «Мониторинг ввода».

macOS не отдаёт «Универсальный доступ» уже запущенному процессу, поэтому перезапуск обязателен.

**Если тумблер в настройках включён, а приложение пишет «запрещён»** — там осталась запись от прежней сборки с другой подписью. Кнопка **«Сбросить и выдать заново»** на вкладке «Права» стирает старые записи (`tccutil reset Accessibility com.davnozdu.llm-dict`), после чего доступ выдаётся начисто.

### Про клавишу 🌐 (Fn)

По умолчанию macOS вешает на неё смену источника ввода. Приложение читает реальную настройку (`AppleFnUsageType`) и говорит, свободна клавиша или нет. Занять её можно двумя способами: выбрать «Ничего не делать» в Системных настройках → Клавиатура → «При нажатии 🌐», либо включить **перехват клавиши** в настройках — тогда её событие не уходит дальше в систему и обычное действие не срабатывает, пока приложение работает.

## Ключ Groq

Бесплатный ключ берётся на [console.groq.com/keys](https://console.groq.com/keys). Вкладка **Настройки** → поле **Ключ** → **Сохранить в Keychain**. Кнопка **Проверить ключ** заодно подтягивает список доступных моделей в выпадающие списки.

Расценки на `whisper-large-v3-turbo` — порядка $0.04 за час аудио.

## Движки распознавания

Три варианта на выбор, переключаются в настройках:

| Движок | Где считает | Модель |
|---|---|---|
| **Groq** | облако | `whisper-large-v3-turbo` и любая другая по OpenAI-протоколу |
| **Parakeet** | локально, ONNX Runtime | NVIDIA Parakeet TDT 0.6B v3 int8, ~640 МБ |
| **Whisper** | локально, whisper.cpp + Metal | large-v3-turbo q5 (574 МБ) или large-v3 q5 (1 ГБ) |

Модели качаются кнопкой из настроек в `~/Library/Application Support/com.davnozdu.LLM-dict/models/` — в приложение они не встроены, иначе `.app` весил бы гигабайты. Обе локальные библиотеки линкуются статически, никаких дополнительных файлов рядом с приложением не нужно.

**Язык речи** выбирается из списка, по умолчанию русский. Автоопределение тоже есть, но стоит лишнего прохода по записи и иногда ошибается на коротких фразах — если язык всегда один, указывать его явно и быстрее, и надёжнее. Parakeet выбор игнорирует: он всегда определяет язык сам, из своих 25 европейских.

Отдельно задаётся **запасной движок**: «если откажет Groq — перейти на Parakeet». Откат срабатывает молча — пропала сеть, кончился лимит, протух ключ, — и диктовка всё равно доводится до конца.

### Про локальные модели для правки текста

Я прогнал кандидатов на роль лёгкого локального корректора — результаты честные, а не обнадёживающие:

| Модель | Русский | Английский | Чешский | Орфография |
|---|---|---|---|---|
| Gemma 3 270M Q4 | отказ | пусто | пусто | — |
| Qwen3 0.6B Q4 (378 МБ) | смысл переписан | частично | не тронут | нет |
| Qwen3 0.6B Q8 (609 МБ) | хорошо | частично | не тронут | нет |
| Qwen3 1.7B Q4 (1.05 ГБ) | хорошо | частично | не тронут | нет |

Чешский не тронула ни одна модель — текст вернулся байт в байт. Орфографию не исправил никто: запятые расставляются, слова нет. Отдельно стоит запомнить, что 0.6B в Q4 ломает смысл, а в Q8 работает — для таких малых моделей Q4 слишком грубое сжатие.

Поэтому llama.cpp в приложение не встроен: тяжёлая зависимость ради модели, справляющейся с одним языком из трёх. Локальная модель при этом доступна — через Ollama или `llama-server` по обычному адресу API, как любой другой поставщик.

### Что быстрее

Замерено на MacBook Pro M2 Pro, 16 ГБ, русская речь:

| Движок | фраза 3.9 с | фраза 14.7 с |
|---|---|---|
| Parakeet TDT int8 | **0.14 с** | **0.45 с** |
| Groq (облако) | 0.60 с | 0.79 с |
| Whisper large-v3-turbo q5 | 1.40 с | 2.53 с |

(язык указан явно; на автоопределении Whisper медленнее примерно в полтора раза)

Parakeet локально обгоняет облако — на коротких фразах вчетверо. Причина в устройстве моделей: Whisper дополняет спектрограмму до фиксированных 30 секунд, поэтому четырёхсекундная фраза стоит ему столько же, сколько тридцатисекундная. Parakeet считает реальную длину записи, а его трансдьюсер перескакивает кадры вместо пошагового обхода.

Проверить на своём железе:

```bash
/Applications/LLM-dict.app/Contents/MacOS/llm-dict --bench запись.wav [язык]
```

Режим прогоняет файл через все установленные движки и печатает время и кратность реального времени.

## Если что-то не срабатывает

Вкладка **Права** показывает, что приложение реально видит:

- **«Сейчас зажато»** — живой список клавиш прямо из системного перехватчика. Зажали сочетание, а здесь пусто или клавиш меньше, чем нажали, — значит до приложения они не доходят, и дело не в настройках.
- **«Прочитать выделенное»** — выделите текст в любой программе, вернитесь и нажмите. Видно, доходит ли выделение.
- **«Последние события клавиатуры»** — сырой список до всякого разбора. Если там нет строк «нажатие» для обычных клавиш, а модификаторы есть, значит система не отдаёт перехватчикам обычные клавиши, и дело не в приложении.
- Счётчик полученных событий: ноль означает, что перехватчик не работает вовсе — обычно из-за «Универсального доступа».

Ещё есть режим, который печатает всё то же в терминал, проходя полный путь приложения — перехватчик, канал, рабочий поток, общее состояние:

```bash
/Applications/LLM-dict.app/Contents/MacOS/llm-dict --watch-keys
```

Тот же список можно получить независимо от приложения, отдельным зондом — он показывает, что видит перехватчик на этой машине:

```bash
swift build/keyprobe.swift
```

Терминалу для этого понадобится «Универсальный доступ».

Проверить связку «промпт → поставщик → модель» отдельно от клавиш и буфера:

```bash
/Applications/LLM-dict.app/Contents/MacOS/llm-dict --test-action "Перевод на чешский" "текст"
```

Кнопка **«Проверить плашку»** в разделе «Диагностика» показывает всплывающую плашку у курсора, не дожидаясь диктовки.

## Действия над текстом

Каждое действие — это промпт, поставщик, модель и своё сочетание клавиш. Из коробки идут перевод на английский, чешский и русский плюс корректура; сочетания намеренно не назначены, чтобы не занять наугад что-то нужное.

Переводов может быть сколько угодно: RU→CS и RU→EN — это два разных действия с разными сочетаниями, и переключать ничего не надо.

У каждого действия есть галочка **«Использовать после диктовки»**. С ней надиктованный текст проходит через этот промпт до вставки: можно причёсывать пунктуацию, а можно сразу переводить. Отмеченных действий может быть несколько — применяются по порядку. Если такое действие не отработало, диктовка не теряется: вставляется распознанное как есть, а о сбое говорит плашка у курсора.

Результат либо ложится в буфер обмена (вставляете сами, ⌘V), либо **сразу заменяет выделенный текст на месте** — выделили, нажали сочетание, текст уже переведён. Выбирается отдельно у каждого действия строкой «Результат», поэтому перевод может заменять на месте, а ответ по данным — ложиться в буфер. О готовности сообщает та же плашка у курсора, что показывает ход диктовки, — системные уведомления для этого не используются: они требуют отдельного разрешения и теряются в центре уведомлений.

Выделенный текст забирается через синтетическое ⌘C — своего API «дай выделенное» в macOS нет. Факт копирования проверяется по счётчику изменений пастборда, а не сравнением текста: иначе повторное копирование того же самого выглядело бы как неудача. Прежнее содержимое буфера при этом затирается, но сохраняется в истории — на вкладке «Буфер» его можно вернуть.

### Ответ по своим данным

У действия можно указать **файл с данными** — markdown или обычный текст со сведениями о вас: чем занимаетесь, какие услуги, график, условия. Выделяете чужое сообщение, жмёте сочетание — и получаете готовый ответ, опирающийся на этот файл.

Язык ответа задаётся не настройкой, а самим сообщением: спросили по-чешски — ответ по-чешски. Иначе пришлось бы держать отдельное действие на каждый язык.

Пример с файлом про мастерскую в Праге:

| Вопрос | Ответ |
|---|---|
| Вы работаете завтра? | Да, завтра я работаю – с 8:00 до 17:00. |
| Kolik stojí diagnostika? | Diagnostika stojí 500 Kč, při objednání opravy je diagnostika zdarma. |
| Do you repair fridges? | Yes, I repair refrigerators. The call-out is free within Prague… |

Готовая заготовка создаётся кнопкой **«+ Ответ по моим данным»** на вкладке «Действия». Модель и поставщик выбираются отдельно для каждого действия, так что под ответы можно поставить модель посильнее, чем под правку диктовки.

Файл перечитывается при каждом запуске — правки подхватываются без перезапуска. Ограничение 256 КБ: содержимое уходит в каждый запрос.

| Поставщик | Адрес | Ключ |
|---|---|---|
| Groq | `api.groq.com/openai/v1` | [console.groq.com/keys](https://console.groq.com/keys) |
| Gemini | `generativelanguage.googleapis.com/v1beta/openai` | [aistudio.google.com/apikey](https://aistudio.google.com/apikey) |
| DeepSeek | `api.deepseek.com/v1` | [platform.deepseek.com](https://platform.deepseek.com/api_keys) |
| Ollama | `127.0.0.1:11434/v1` | не нужен |
| Ollama Cloud | `ollama.com/v1` | [ollama.com/settings/keys](https://ollama.com/settings/keys) |
| Свой адрес | любой OpenAI-совместимый | по обстоятельствам |

Все они говорят на OpenAI-совместимом протоколе, поэтому код один на всех — у Gemini для этого есть отдельный совместимый эндпоинт. Ключи хранятся в связке ключей по одному на поставщика.

Кнопка **«Считать модели»** запрашивает у поставщика список и превращает поле модели в выпадающий список — не нужно помнить точные названия.

Рядом есть **«Проверить ключ»**, и это не то же самое: у части поставщиков, в том числе у Ollama Cloud, список моделей отдаётся вообще без ключа. Успешное чтение списка поэтому ничего не доказывает — проверка делает короткий настоящий запрос к модели. Там же видно, сохранён ли ключ на самом деле: набранное в поле ещё не значит сохранённое.

## Внешние LLM и локальные серверы

| Что | Поле | Значение |

| Ollama | Обработка текста → Адрес API | `http://127.0.0.1:11434/v1` |

## Сборка

Сборка идёт в GitHub Actions на `macos-14` (Apple Silicon), Xcode не требуется — хватает Command Line Tools и `cmake` (whisper.cpp собирается из исходников).

Локально:

```bash
cargo build --release
build/bundle.sh target/release/llm-dict 0.1.0
SIGN_IDENTITY="LLM-dict Self Signed" build/sign.sh
open dist/LLM-dict.app

# при желании собрать образ
build/dmg.sh dist/LLM-dict.app 0.1.0
```

Подписывать локальную сборку тем же сертификатом, что и CI, — не придирка. Два бандла с одинаковым `CFBundleIdentifier`, но разной подписью macOS считает разными программами: заводит на них отдельные записи разрешений, показывая в списке один пункт. Получается «тумблер включён, а доступа нет». Импортировать сертификат в локальную связку:

```bash
build/setup-local-cert.sh cert.p12 cert.pem
```

Без сертификата `build/sign.sh` подпишет ad-hoc — для разовой проверки годится, но копию потом лучше удалить.

### Про подпись, разрешения и карантин

Тут три разных вещи, которые легко перепутать.

**Карантин** ставит тот, кто скачал файл — браузер. Снять его без ручного `xattr` может только нотаризация Apple, а она требует платного Developer ID. Зато образ, скачанный самим приложением при обновлении, карантина не получает: ручной шаг нужен ровно один раз, при первой установке.

**Разрешения** («Универсальный доступ», микрофон) macOS привязывает к подписи. При ad-hoc подписи хеш меняется с каждой сборкой, и после обновления разрешения слетают.

**Связка ключей** тоже помнит подпись: ACL записи привязан к приложению, и при нестабильной подписи macOS считает новую сборку чужой программой и переспрашивает пароль.

Обе последние проблемы решает самоподписанный сертификат — он бесплатный. Репозиторий уже настроен на него через секреты `MACOS_CERT_P12`, `MACOS_CERT_PEM` и `MACOS_CERT_PASSWORD`; если их удалить, CI вернётся к ad-hoc подписи.

Свой сертификат делается так:

```bash
openssl req -x509 -newkey rsa:2048 -keyout key.pem -out cert.pem -days 3650 -nodes \
  -subj "/CN=LLM-dict Self Signed/O=ваше-имя" \
  -addext "keyUsage=critical,digitalSignature" \
  -addext "extendedKeyUsage=critical,codeSigning" \
  -addext "basicConstraints=critical,CA:false"
openssl pkcs12 -export -out cert.p12 -inkey key.pem -in cert.pem -name "LLM-dict Self Signed"

base64 -i cert.p12 | gh secret set MACOS_CERT_P12
base64 -i cert.pem | gh secret set MACOS_CERT_PEM
gh secret set MACOS_CERT_PASSWORD
```

## Устройство

```
клавиша (CGEventTap, отдельный CFRunLoop)
   ↓
запись с микрофона (cpal) → 16 кГц моно → WAV
   ↓
POST /audio/transcriptions
   ↓  (если включена обработка)
POST /chat/completions
   ↓
буфер обмена + синтетический ⌘V → возврат прежнего буфера
   ↓
запись в history.jsonl
```

| Файл | Что делает |
|---|---|
| `src/hotkey.rs` | слежение за клавишей через CGEventTap |
| `src/audio.rs` | запись, приведение к 16 кГц моно, WAV |
| `src/providers.rs` | клиенты к OpenAI-совместимому API |
| `src/stt.rs` | три движка распознавания за общим интерфейсом |
| `src/models.rs` | каталог локальных моделей и их загрузка |
| `src/provider.rs` | поставщики моделей и их адреса |
| `src/actions.rs` | действия над выделенным текстом |
| `src/insert.rs` | вставка текста под курсором |
| `src/engine.rs` | состояние и рабочий поток конвейера |
| `src/app.rs` | окно: статус, настройки, история, буфер, права |
| `src/binding.rs` | сочетания клавиш и коды клавиш macOS |
| `src/conflicts.rs` | проверка, не занято ли сочетание системой |
| `src/permissions.rs` | проверка и запрос разрешений macOS |
| `src/autostart.rs` | LaunchAgent для запуска при входе |
| `src/updater.rs` | проверка и установка обновлений |
| `src/logging.rs` | журнал в файл и в stderr |
| `src/overlay.rs` | плашка у курсора нативным окном |

Настройки и история лежат в `~/Library/Application Support/com.davnozdu.LLM-dict/`, журнал — в `~/Library/Logs/LLM-dict/llm-dict.log`. Обе папки открываются кнопками в разделе «Диагностика» настроек.

Если диктовка не сработала, смотреть надо в двух местах: вкладка «История» покажет, что именно ответил сервис, а журнал — что происходило до этого. Самая частая ошибка — ключ от одного сервиса при адресе API от другого; теперь приложение прямо об этом и пишет.
